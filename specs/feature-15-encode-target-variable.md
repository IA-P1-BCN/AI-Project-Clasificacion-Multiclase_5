## Goal

Provide a single, leakage-free way to encode the target `Cover_Type` (labels
1-7) into the 0-6 integer labels that the models expect, and persist the
label -> class-name mapping so the app can turn a numeric prediction back into
a human-readable cover type at inference time.

## Scope

- In scope: a deterministic target encoder (`Cover_Type` 1-7 <-> encoded 0-6),
  the canonical `Cover_Type` -> class-name mapping as the single source of
  truth, a reproducible JSON artifact with the mapping for the app, and a
  consistency check (round-trip + full class coverage).
- Out of scope: feature preprocessing/scaling (#14), the split protocol (#16),
  imbalance handling (#17), model training (#20, #22), exporting the fitted
  pipeline for the app (#32), the app UI that will consume the mapping (M6),
  unit tests (#40). `src/gradient_boosting.py` (#22, merged) already does an
  ad-hoc `y - 1` and keeps its own `CLASS_NAMES`; refactoring it to import from
  this module is left to its owner and noted here as the boundary.

## Design

| File | Change |
|---|---|
| `src/target_encoding.py` | New. Canonical `CLASS_NAMES`, `encode_target()`, `decode_target()`, `label_mapping()`, `save_mapping()`, `load_mapping()`, `check_encoding()`, `main()`. |
| `docs/PREPROCESSING.md` | New section *Target encoding*. |

Decisions:

- **Fixed, data-independent mapping.** The class set is fixed by the ontology
  (`Cover_Type` 1-7), so the encoding is a deterministic shift `encoded =
  Cover_Type - 1` (0-6) rather than a fitted `LabelEncoder`. Nothing is learned
  from data, so there is no fit step and therefore no way to leak. This matches
  the `y - 1` already used in `src/gradient_boosting.py` and the 0-indexed
  labels XGBoost/LightGBM require.
- **`encode_target` / `decode_target` are pure** and validate their input
  (every value must be a known label), so an unexpected class fails loudly
  instead of producing a silent off-by-one.
- **Canonical `CLASS_NAMES`** (`Cover_Type` -> species name) lives here as the
  single source of truth, taken from `specs/ontology.md`.
- **Persisted artifact for the app:** `save_mapping()` writes
  `models/label_mapping.json` (encoded label -> `Cover_Type` + class name).
  Like every other artifact it is git-ignored and regenerated by running the
  module; the mapping is static reference data, not a trained model.
- **No new dependency** (`json`, `pathlib` from the standard library; reuses
  `load_raw`, `TARGET`, `clean`).

## Acceptance criteria

- [x] Map class labels to integers (`Cover_Type` 1-7 -> 0-6)
- [x] Store the label -> class mapping for the app
- [x] Verify encoding is consistent (round-trip + full class coverage)
- [x] Target encoded and mapping saved for inference

## Verification

Run with `python src/target_encoding.py`:

- `check_encoding()` passes on the cleaned dataset: the 7 labels map to 0-6,
  `decode_target(encode_target(y))` equals `y`, and all 7 classes are present.
- `models/label_mapping.json` is written with 7 entries, each giving the
  encoded label, the original `Cover_Type` and the class name.
- `main()` prints the mapping table and the encoded class distribution.
